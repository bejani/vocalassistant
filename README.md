# Vocal Assistant — دستیار صوتی اندروید

این پروژه یک نمونه Native Android با Kotlin است که برای استفاده در خودرو طراحی شده است. برنامه با عبارت **«سلام یولداش»** فعال می‌شود، سپس فرمان «تماس بگیر» یا «زنگ بزن» را تشخیص می‌دهد و قبل از تماس، به‌صورت صوتی درخواست تأیید می‌کند. تماس فقط پس از تشخیص عبارت‌هایی مانند «تأیید می‌کنم»، «تأیید» یا «بله» انجام می‌شود.

## نکته مهم درباره پردازش صدا

این نسخه هیچ مدل صوتی حجیمی را داخل APK قرار نمی‌دهد. تشخیص گفتار از `android.speech.SpeechRecognizer` و موتور گفتار نصب‌شده روی گوشی استفاده می‌کند؛ بنابراین حجم برنامه و مصرف فضای ذخیره‌سازی پایین می‌ماند، اما عملکرد آن به در دسترس بودن موتور تشخیص گفتار و اتصال شبکه یا پشتیبانی آفلاین همان موتور بستگی دارد. اگر گوشی در ایران نتواند سرویس گفتار پیش‌فرض را در دسترس قرار دهد، راه‌حل بعدی استفاده از یک مدل آفلاین مانند Vosk است که به فضای ذخیره‌سازی و RAM بیشتری نیاز دارد.

## اجرا در Android Studio

پروژه را با گزینه **Open** روی پوشه ریشه باز کنید. سپس اجازه دهید Gradle Sync انجام شود و از مسیر `Build > Make Project` کامپایل کنید. برای اجرای واقعی، یک گوشی Android با API 26 یا بالاتر و موتور تبدیل گفتار فعال لازم است.

پس از نصب، از برنامه یک مخاطب دارای شماره تلفن انتخاب کنید، مجوزهای میکروفون، مخاطبین و تماس را بدهید و گزینه **شروع دستیار صوتی** را بزنید. اندروید یک اعلان foreground نمایش می‌دهد؛ این اعلان برای شفافیت دسترسی مداوم به میکروفون ضروری است.

## محدودیت‌های شبکه در ایران

وابستگی‌های پروژه فقط از Google Maven و Maven Central دریافت می‌شوند. در صورت اختلال دسترسی، می‌توان mirror سازمانی یا mirror قابل‌دسترسی را در فایل `settings.gradle.kts` فعال کرد. خطوط mirror به‌صورت کامنت قرار داده شده‌اند تا بدون بررسی شبکه فعال نشوند؛ mirror نامعتبر یا ناشناس می‌تواند باعث خطای Sync یا دریافت بسته نادرست شود. پس از اولین Sync موفق، Gradle وابستگی‌ها را در cache نگه می‌دارد.

## امنیت

این پروژه به کلید API نیاز ندارد و هیچ کلید، رمز عبور یا توکن GitHub در کد قرار نمی‌گیرد. اگر در آینده سرویس ابری برای تشخیص گفتار اضافه شد، کلید آن باید فقط در سرور یا Secretهای CI نگهداری شود و هرگز در `gradle.properties` قابل commit یا فایل‌های Kotlin قرار نگیرد.

## محدودیت‌های نسخه اول

عبارت بیدارباش در این نسخه با شنودهای کوتاه و پیوسته SpeechRecognizer بررسی می‌شود و یک hotword engine اختصاصی کم‌مصرف نیست. برای استفاده طولانی‌مدت، رفتار سرویس به موتور گفتار دستگاه و محدودیت‌های سازنده گوشی وابسته است. همچنین تماس با مخاطب انتخاب‌شده انجام می‌شود؛ تشخیص نام مخاطب از فرمان آزاد در این نسخه پیاده‌سازی نشده است.
